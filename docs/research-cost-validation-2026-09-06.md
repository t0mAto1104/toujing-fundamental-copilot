# 研究流程成本优化验收（2026-09-06）

## 已实现

- 保持默认/用户选定模型、六章研究框架、两段各 5200 输出 Token 预算、原文段落/表格抽取及真实性校验不变。
- HTTP 资料先做保守的补证缺口识别，至多补两项；达到日期、正文、主题覆盖及多期三表条件时跳过模型 collect。此规则只规划检索，不是证据置信度或真实性证明；模型仍必须核验资料、披露缺口。
- 已完成的公开补证通过现有 D1 快照保存 6 小时，按证券身份、正文/期间/来源内容及缺口版本指纹复用。不含用户问题、用户身份、模型生成的报告或行情；来源内容变化即失效。既有 HTTP 正文缓存继续复用。
- 用户写作检查点仍按用户、模型、证券和问题隔离，1 小时内重试只补失败阶段；研究组 ID 跨重试保持一致。
- 短证据去重并路由到业务/财务；交叉主题和不明主题保留给两段，另一段仍接收带期间及来源的事实提要。保留反证、多期事实、独立来源；不截断原始表格。
- Astra/5.6 研究请求显式缓存固定开发者规则，动态资料不设缓存写入断点；5.4/5.5 保留原兼容请求格式。未增加定时 AI 请求。
- 后台保存研究组、缓存读取/写入、实际服务档位、请求时价目版本及 USD 估算。历史缺失字段、未返回用量和未核实档位显示未知；缓存读写属于输入，推理属于输出，不重复加总。
- 恢复证据包时对超时/无效时点的行情单独刷新；失败保留旧值并明确标记。复用写作不冒充重新生成估值结论。

## 离线验证

共 50 项测试通过：research-cost（4）、research-budget（8）、research-framework（16）、research-calculations（1）、research-data（11）、research-models（2）、research-access（8）。所有 OpenAI 请求均为隔离模拟，没有真实模型开销。

重点覆盖：跳过 collect 的完整调用链；切换用户/模型/问题只复用公开资料；资料过期重新补证；一个写作分段超时后只重试失败分段；保留六章/原始财务/来源；恢复旧报告时单独刷新行情；新旧模型缓存参数兼容；生成迁移在旧 SQLite 表上应用后日志读写正确；未知费用不记为零；非管理员不能访问审计数据。

TypeScript、变更文件 lint 和生产构建通过。D1 新增迁移为 `0004_ai_usage_cost_details.sql`，仅新增 6 个可空列，无数据回填、删除或历史迁移改写；发布时由平台应用。

## 边界与后续验收

- 未运行付费的同公司/同材料 A/B 质量验收，不能据离线测试声称真实报告质量已经等价，亦不能声称已实测节省某个百分比。下一轮应以富祥股份研究标准核对事实、期间、会计口径、因果推导、具名同行及反证，再对照真实账单。
- 缺口规划是确定性检索提示，不是全文语义审计。首次研究存在关键缺口时仍会调用 collect；缓存只复用有效期内已有公开补证，不表示所有证据已齐全。
- 公开补证采用已完成快照复用，没有跨 Worker 的付费并发合并锁。不同用户同时首次研究同一公司仍可能各自收集；不共享跨请求 I/O Promise，避免 Cloudflare 请求上下文问题。
- USD 是官方标准价估算，不是发票。价目依据 2026-09-06 官方定价及各模型页；未知服务档位不估价。未来价格变动需更新价目版本；历史估算不回算。
- 本轮仅修改及验证，未公开部署或执行生产数据库迁移。

参考：[官方定价](https://developers.openai.com/api/docs/pricing)、[Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)。
