# 搜索与公司数据超时修复验收

## 原因与已复现证据

- 原东方财富全局 Promise 队列未将排队时间纳入超时；搜索接入此队列后，被研报/资料慢请求拖住。线上珠免集团搜索出现约 53 秒及 150 秒后取消，公司数据请求多次约 30 秒被页面取消。
- 原超时计时器在返回响应头后即清除，正文读取没有截止时间，且调用者 AbortSignal 被覆盖。
- 首页两个响应式搜索框同时挂载、共享输入，均会查询；中文输入法组合输入期间也查询。公司页每 20 秒刷新时重新搜索证券。

## 修复范围

- 按上游域名分离串行通道；域内启动间隔至少 1.1 秒，跨通道总启动间隔至少 750 毫秒。共享的只有有期限的租约数据，不再共享正在进行的 I/O Promise。搜索不等待其他域名的响应完成。
- 超时包含排队、连接、正文读取；传播调用者取消；取消/过期请求不迟到发送，失效租约可恢复。
- 搜索总预算 8 秒，前端 10 秒保护；仅聚焦的搜索框查询，中文输入组合期间暂停，失焦/提交/选择时取消。
- 真实证券查询结果缓存 5 分钟，已核验证券身份缓存 24 小时，使用现有 D1 data_snapshots，无新表。仅缓存成功匹配，不缓存空结果或错误，不缓存用户伪造的 listing 对象。
- 公司页复用与当前查询匹配的已核验身份；指定上市地失配时不静默选择其他证券。主请求总预算 12 秒，资料快返回预算 2 秒、行情 3 秒，前端 15 秒保护；后台继续保存已取得的真实资料。
- 慢行情完成后写入共享缓存，下次刷新可读取。失败时保留真实旧报价并标记未更新，不将旧报价标成最新。
- 公司资料汇总受 20 秒截止时间保护，HTTP 请求可取消；公司缓存不复用跨 Worker 请求的 I/O Promise；资料全部失败不覆盖旧缓存。隐藏标签页停止公司轮询。
- 未新增 OpenAI 调用、定时 AI 任务或 API Key，未更改研究模型、金融数值计算、账户权限或数据库结构。

## 验证

- 隔离 HTTP 故障注入：慢研报不阻塞搜索；排队计入截止；正文卡住超时；已取消及排队中取消请求不发送；正文读取中取消；旧队列拥有者过期后恢复。
- 实际公司路由 + 隔离 SQLite：慢资料先返回 200 与 pending；证券身份写入 D1；后续刷新不再请求搜索源；行情失败保留真实旧报价并标记；上市地失配拒绝；取消请求不查询。
- 回归包含原北交所京A、证券前后缀、非金融查询、未登录 AI 拒绝、权限与报告存储测试。
- 本地真实接口：珠免集团联想 994ms、维琪科技联想 331ms；珠免集团首次公司数据 2038ms（行情已返回、资料 pending），资料完成后 171ms（6 项财务科目、公司资料）；维琪科技资料完成后 571ms（公司资料、2 篇研报）。本次巨潮公告未返回可用记录；北交所新浪财务源不覆盖，继续明确显示缺失。
- 不进行未经请求的浏览器视觉/点击验收；已进行 API、类型、构建及离线回归验证。

用户于验收后确认公开发布本次超时修复；部署结果以 Sites 发布状态为准。
