# 自定义研报：按证据范围形成结论

2026-09-26 · 结论验收版本 `scoped-conclusion-v1`。

原实现将任意 `warnings`、检索缺口、财务质量问题或失败检查视为整体结论否决条件。现在区分：

- **条件分析**：核心财务覆盖、来源和一致性检查通过，保留原分析；辅助缺口及未完整读取全文的边界另列，不声称已完成全面审计。
- **局部分析**：原综合判断可能依赖被排除模块时，仅在模板篇幅内摘取其他可用模块的完整句，并同步事实、反证、验证变量和引用。不拼造数字或增加模型调用。
- **暂缓综合判断**：没有足够的可用分析。保留具体受限原因，不将缺口解释为公司中性、无风险或零值。

无效来源、交易建议、把已取得数据误称缺失、文字完整性损坏等仍检查。新增对涉及已知财务来源冲突／口径问题的模块拦截。资料时效或核心数值不足时不形成全面财务／估值判断；银行不强制使用制造业现金流兑现规则。

资料可得性缺口仅在明确的同期间数值或对应正式披露全文确实取得时关闭，并记录原缺口和证据来源。复合缺口、附注明细、不同报告期、历史比较及不能确定的缺口继续保留。范围匹配是保守的文本规则，不是对任意文字因果或每个数字的语义审计。

## 兼容与成本

- 不改变写作 JSON 或成功分段的检查点版本，不强迫已完成的付费步骤重跑。
- `conclusionReview` 为可选字段，随已有报告 JSON 存储；不需要数据库迁移。
- 历史已保存报告仍按原始结果打开，不自动改写、重新生成或收费。新报告及未完成任务的重新组装使用新规则。
- 默认 7 模块、简版／深度版、篇幅预算、原界面风格和真实性边界保持不变。

## 验证

`tests/research-conclusion.test.ts` 使用完全离线合成证据验证辅助缺口、估值超时、旧季度缺失、全文部分读取、来源无效、财务冲突、过期数据、完全无证据、缺口关闭、篇幅与引用、序列化和旧报告渲染。

`tests/research-conclusion-ui.html` 是不调用任何 API 的展示测试页，检查三种范围、全部原因定位及来源记录。不是生产页面，也不代表真实公司数据。
