# 银行研究数据与正文完整性修复

日期：2026-09-25 至 2026-09-26。针对农业银行报告暴露的问题修复共用研究链路，不为单个证券硬编码财务值。

## 修复范围

1. **统一财务字段映射**：识别“归属于母公司的净利润”等同义科目及已核验的新浪字段标识，保留原始科目和来源；表格、历史图、同比、事实账本和一致性检查使用相同解析结果。“净利润”不替代“归母净利润”，“利息收入”不替代“净利息收入”；矛盾映射拒绝使用。
2. **银行研究方向**：优先使用有来源的公司行业字段，其次使用真实行业板块交集，最后使用正式披露中的严格主营自述。不根据公司名称、新闻或模型猜测行业。银行重点检查净息差、不良率、拨备与资本充足率，不再把库存、商品期货等制造业指标列为银行数据缺口。
3. **历史估值保留与失败分类**：成功快照使用跨日稳定缓存键；暂时性失败最多重试一次，仍受原有 25 秒总预算约束。403、429、结构错误不进行重试。单个指标缺失保留其他有效指标；缺失不填零，失败不存为成功快照。有日期但所有指标均为空的响应同样不覆盖旧有效快照，真实数值 0 不被误判为空。区分超时、访问限制、解析/校验失败与来源无记录。
4. **定向补读披露与行业研报**：保存已找到但未读成功的公告地址，在既有 35 秒补采预算内优先补最新完整年报、半年报，最多两份。行业只在正文读取后才确认时，补取原先跳过的近期行业研报。维持来源白名单、证券身份、报告期和全文读取校验。
5. **完整句与模板语义**：保持现有模块字数和模型输出预算，要求在预算内完整概括；残句不直接展示，优先保留完整句并提示需核验。不因残句自动重跑付费模型。简版的默认标题明确为简版，保留用户自定义标题。
6. **长年报读取**：移除页面遍历中的 400 页硬截断，统一使用读取器既有的 1000 页安全上限。PDF 解析时长、文件大小和提供给模型的摘录上限均未增加。遍历成功不等于模型接收全文：模型仍只接收带页码的有限相关摘录。

研究检查点和资料缓存版本已更新，避免新任务继续复用旧解析结果。已有已保存报告和 PDF 不会被静默改写。

## 无付费模型的真实数据核验

- 新浪农业银行 `2026-06-30` 财报：归母净利润原值 `146381000000` 元，程序指标显示 **1463.81 亿元**；与总净利润保持区分。
- 新浪同期间 `NETINTEINCO` / “净利息收入”原值 `312244000000` 元，银行指标显示 **3122.44 亿元**。
- 东方财富历史估值实取 **1212 条**，最新记录为 **2026-09-24**。单次成功不代表未来接口永不超时，失败时仍须显示真实日期和原因。
- [农业银行 2025 年年度报告](https://static.cninfo.com.cn/finalpage/2026-03-31/1225056196.PDF)：修复前最多遍历 400/418 页；修复后在原解析预算内遍历 **418/418 页**，413 页提取到文字，读取器判定完整，相关摘录共 14184 字符。
- 第 127 页“本行主要业务为提供银行及相关金融服务”的正式自述已纳入严格识别回归，同时保留银行软件、云服务供应商的负例。

上述核验仅调用公开金融数据和正式披露 HTTP 来源，未发起 OpenAI 请求。
